Django Notes App

A Django and MySQL notes application served by Nginx and containerized with Docker Compose. Deployed on an AWS EC2 server, the whole stack builds and starts with a single Docker command.

Overview Architecture Docker files Run on EC2 Problems and fixes Commands

Overview

The app is a notes website written in Django. Notes are stored in MySQL. Nginx sits in front and forwards web traffic to Django. Everything runs as three Docker containers started by one command.

Ports

Service Port Used for
Nginx 80 Public entry to the notes app
Django 8000 Application server inside the stack
MySQL 3306 Database, reachable only from other containers
SSH 22 Your own login to the server

Open ports 80 and 8000 in the EC2 security group to reach the app, and limit port 22 to your own IP.

Docker files

Dockerfile for the Django container

The original file had no start command, so a container started from it ran plain python3 and exited with code 0. The last line below fixes that. Migrations run when the container starts, because MySQL is not available while the image is being built.

Dockerfile 
FROM python:3.9

            WORKDIR /app/backend

            COPY requirements.txt /app/backend
            RUN apt-get update \
            && apt-get upgrade -y \
            && apt-get install -y gcc default-libmysqlclient-dev pkg-config \
            && rm -rf /var/lib/apt/lists/*

            # Install app dependencies
            RUN pip install mysqlclient
            RUN pip install --no-cache-dir -r requirements.txt

            COPY . /app/backend

            EXPOSE 8000

            CMD ["sh", "-c", "python manage.py migrate && python manage.py runserver 0.0.0.0:8000"]

.dockerignore

This file keeps the MySQL data folder out of the build. Without it, Docker tries to read files owned by the MySQL container and the build stops with a permission error. The file name starts with a dot, has no extension, and sits next to the Dockerfile.

.dockerignore 
data/
            .git
            __pycache__/
            *.pyc

docker-compose.yml layout

The three container names come from your project. The layout below is the recommended shape. Keep your own environment values, and replace the old ./data/mysql/db folder mount with a named volume so MySQL files never appear in the project folder.

docker-compose.yml (recommended) 
services:
            db:
            image: mysql
            container_name: db_cont
            restart: always
            environment:
            MYSQL_ROOT_PASSWORD: change-me
            MYSQL_DATABASE: notes_db
            volumes:
            - mysql_data:/var/lib/mysql
            healthcheck:
            test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
            interval: 10s
            timeout: 5s
            retries: 10
            networks:
            - notes-app

            django_app:
            build: .
            container_name: django_cont
            restart: always
            ports:
            - "8000:8000"
            depends_on:
            db:
            condition: service_healthy
            networks:
            - notes-app

            nginx:
            build: ./nginx
            container_name: nginx_cont
            restart: always
            ports:
            - "80:80"
            depends_on:
            - django_app
            networks:
            - notes-app

            volumes:
            mysql_data:

            networks:
            notes-app:
Check before using. The service names, the ./nginx build folder, the database name and the password are placeholders. Match them to your real file. Remove the version: line if it is still there, since Compose now ignores it and prints a warning.

Run on EC2

1. Install Docker, Compose and Git

sudo dnf update -y
            sudo dnf install -y docker git
            sudo systemctl enable --now docker
            sudo usermod -aG docker ec2-user
            # log out and log back in so the docker group applies

Install the Compose plugin if docker compose version is not found:

sudo mkdir -p /usr/local/lib/docker/cli-plugins
            sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 \
            -o /usr/local/lib/docker/cli-plugins/docker-compose
            sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
            docker compose version

Compose builds also need Buildx 0.17.0 or later. If you see compose build requires buildx 0.17.0 or later, install a newer plugin:

sudo mkdir -p /usr/local/lib/docker/cli-plugins
            sudo curl -SL https://github.com/docker/buildx/releases/download/v0.19.3/buildx-v0.19.3.linux-amd64 \
            -o /usr/local/lib/docker/cli-plugins/docker-buildx
            sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-buildx
            docker buildx version

2. Get the code

git clone https://github.com/itsmedaksh3048-blip/Django_Notes_App.git
            cd Django_Notes_App

3. Build and start

docker compose up --build -d
            docker compose ps

All three containers should show Up. Then open http://<ec2-public-ip> for Nginx, or http://<ec2-public-ip>:8000 for Django directly.

4. Update after a code change

cd Django_Notes_App
            git pull origin main
            docker compose down --remove-orphans
            docker compose up --build -d

Do not add -v to docker compose down unless you want to delete the MySQL data.

Keeping the same IP

A stopped and restarted EC2 instance gets a new public IP. A reboot keeps it. Attach an Elastic IP to keep one address. An Elastic IP on a stopped instance is billed, so release it when you do not need it.

Problems and fixes

Each entry shows the symptom you saw and what resolved it.

Docker

Compose build requires Buildx 0.17.0 or later

compose build requires buildx 0.17.0 or later

The Buildx plugin that ships with Amazon Linux Docker is too old.

Fix: install a newer Buildx plugin into /usr/local/lib/docker/cli-plugins, as shown in the Run on EC2 section.

Docker

Permission denied while loading the build context

error from sender: open data/mysql/db/#innodb_redo: permission denied

The MySQL container wrote its files into data/mysql/db inside the project folder as its own user. Docker could not read them when it sent the folder to the build. The log line load .dockerignore, transferring context: 2B showed that no ignore file was in use.

Fix: add a .dockerignore containing data/. Delete the leftover folder once with sudo rm -rf data from the project folder. For a lasting fix, store MySQL data in a named volume instead of a folder in the project.

Docker

Port 8000 is already allocated

Bind for 0.0.0.0:8000 failed: port is already allocated

ss -tlnp showed docker-proxy still holding port 8000 although no container used it. This is a stale forwarder left by a removed container.

Fix: run sudo systemctl restart docker, check that sudo ss -tlnp | grep 8000 prints nothing, then start the stack again. Running docker compose down --remove-orphans before every start keeps old containers from holding ports.

Container

Container starts and exits straight away

Exited (0), command "python3"

The image had no CMD, so Docker ran the Python interpreter, which closes when there is no terminal. The earlier django_cont also showed Restarting (1), which means the app crashed on start, often because MySQL was not ready.

Fix: add the CMD line to the Dockerfile, and make Django wait for MySQL with a health check and depends_on. Read the cause with docker logs <name>.

Info

Warning that the version attribute is obsolete

Compose prints this warning because the top version: line in docker-compose.yml is no longer used. It is harmless. Delete the line to remove it.

Commands

Run and manage the stack

cd Django_Notes_App
            docker compose up --build -d
            docker compose ps
            docker compose logs -f django_app
            docker compose down --remove-orphans

Run a single image

docker run -d -p 8000:8000 --name notes notes-app:latest
            docker logs notes
            docker stop notes
            docker rm -f notes

A lone Django container cannot reach MySQL, so use Compose for the full app.

Clean up Docker

Goal Command
Remove all containers, running or stopped docker rm -f $(docker ps -aq)
Remove all images docker rmi -f $(docker images -aq)
Remove unused containers, images, networks and cache docker system prune -a -f
Also remove volumes (deletes MySQL data) docker system prune -a --volumes -f
Remove only this project including its volumes docker compose down -v --remove-orphans

Inspect and troubleshoot

Goal Command
List all containers docker ps -a
See why a container stopped docker logs <name>
Read the exit code docker inspect <name> --format '{{.State.ExitCode}}'
Find what holds a port sudo ss -tlnp | grep 8000
Restart Docker sudo systemctl restart docker

Add a swap file

The EC2 instance has about 2 GB of memory and no swap. A swap file keeps builds from running out of memory. 

sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
            sudo chmod 600 /swapfile
            sudo mkswap /swapfile
            sudo swapon /swapfile
            echo '/swapfile swap swap defaults 0 0' | sudo tee -a /etc/fstab
Passwords and key files stay out of this page and out of GitHub.
